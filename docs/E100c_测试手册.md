## 2. 端口和配对

### 2.1 网卡和 E100c 的连接

| 网卡 | PCI BDF | NUMA | 主机 PCIe 交换芯片 | 接 E100c |
|---|---|---|---|---|
| ens108np0 | 0000:73:00.0 | 0 | 6e | die1 chip0 |
| ens111np0 | 0000:dd:00.0 | 1 | da | die1 chip1 |
| ens103np0 | 0000:62:00.0 | 0 | 5d | die1 chip2 |
| ens114np0 | 0000:e0:00.0 | 1 | da | die1 chip3（**网卡已掉出 PCIe，暂时不可用**） |
| ens101np0 | 0000:60:00.0 | 0 | 5d | die0 chip0 |
| ens119np0 | 0000:f1:00.0 | 1 | eb | die0 chip1 |
| ens110np0 | 0000:dc:00.0 | 1 | da | die0 chip2 |
| ens106np0 | 0000:71:00.0 | 0 | 6e | die0 chip3 |

每个 chip 都用 E100c 的 ETH 物理 port 0。E100c 两个 die 的管理地址：die0 是 `-s 0x38`，die1 是 `-s 0x39`。

### 2.2 路由规则

请求从一个 die 进 E100c，由请求里的 **user.port** 字段决定从另一个 die 的哪个 chip 出去：

> 从 die X 进、user.port = p 的请求，从另一个 die 的 **chip (p xor 2)** 出去。两个方向规则相同。

| user.port | 出口 chip |
|---|---|
| 0 | 另一个 die 的 chip 2 |
| 1 | 另一个 die 的 chip 3 |
| 2 | 另一个 die 的 chip 0 |
| 3 | 另一个 die 的 chip 1 |

反过来，要从某个 chip 出去，user.port = 目标 chip xor 2。同一个 die 内的两个口之间不能互发。

响应原路返回，到发出请求的那个网口。反射端回写响应（B）时带一个 b-port（`--b-port`），实测的填法：

- 反射端在 **die0**（请求从 die1 发）：b-port 填 0 即可。
- 反射端在 **die1**（请求从 die0 发）：b-port 必须填 **发送口所在 chip xor 2**，否则写响应回不去。

脚本里每个对口的 user.port 和 b-port 都已经填好，用脚本时不用自己算。

### 2.3 脚本里的对口

`./scripts/e100c.sh <对口> ...` 的第一个参数选对口。

**主对口**（die1 发，die0 反射）：

| 对口 | 发送口 → 反射口 | E100c 路径 | user.port |
|---|---|---|---|
| `0` | ens108 → ens110 | die1 chip0 → die0 chip2 | 0 |
| `1` | ens111 → ens106 | die1 chip1 → die0 chip3 | 1 |
| `2` | ens103 → ens101 | die1 chip2 → die0 chip0 | 2 |
| `3` | ens114 → ens119 | die1 chip3 → die0 chip1 | 3（ens114 掉线，暂不可用） |

**反方向**（die0 发，die1 反射），用于双向打流：

| 对口 | 发送口 → 反射口 | 说明 |
|---|---|---|
| `r0`~`r3` | `0`~`3` 的反方向，如 `r0`：ens110 → ens108 | 和正方向一起跑时两边都加 `--iso`；最多 `-f 4`、`-r 4` |
| `b1` | ens106 → ens111（`1` 的反方向） | 8 流 + 8 核反射的核布局；不能和 `2`、`3`、`b2` 并发 |
| `b2` | ens101 → ens103（`2` 的反方向） | 8 流 + 8 核反射的核布局；借用 `0`、`1` 的核，不能和它们并发 |

**交叉路由**：

| 对口 | 发送口 → 反射口 | 说明 |
|---|---|---|
| `z1` | ens111 → ens110（die1 chip1 → die0 chip2，user.port 0） | 和直连 `d1` 用同一对网卡和核，用来比时延；和 `0` 用同一个出口 |
| `v3` | ens110 → ens111 | `z1` 的反方向 |

**直连**（网线直接对接两个网口，不经过 E100c；要先改线）：

| 对口 | 直连的两个口 |
|---|---|
| `d0` | ens108 ↔ ens103 |
| `d1` | ens111 ↔ ens110 |
| `d2` | ens106 ↔ ens101 |

**别名**：`y0`、`w2`、`y3` 分别等于 `0`、`2`、`3`（报告里用过的名字）。`e100c_r` 等于 `b2`。`e100c_r1`、`e100c2`、`x1`、`xa`、`xb` 是旧接线用的，已停用。

### 2.4 能不能同时跑

每个对口在脚本里有固定的核。两个对口用了同一批核时不能同时跑，否则两边都会变慢或起不来。

- `0`、`1`、`2`、`3` 之间可以同时跑，`r0`~`r3` 也可以和它们同时跑（加 `--iso`）。
- `b1`、`b2`、`z1`、`v3` 借了别的对口的核，限制写在上表和脚本的注释里。
- 不确定时用 `--dry-run` 看两条命令的 `--lcores` / `-l` 有没有重叠。

### 2.5 新增配对

需要新的发送口、反射口组合时：

1. 查[网卡表](#21-网卡和-e100c-的连接)，两个口必须在不同的 die。
2. user.port = 反射口所在 chip xor 2。
3. 反射口在 die1 时，b-port = 发送口所在 chip xor 2；反射口在 die0 时 b-port = 0。
4. 在 `scripts/e100c.sh` 里照已有的块加一个 `case`：网卡名、BDF、发送核（`SND_MAIN`、`SND_TX`、`SND_RX`）、反射核（`REFL_MAIN`、`REFL_C0`），核放在网卡所在的 NUMA，且不要和要并发的对口重叠。
5. 先 `ping` 打通，再跑性能。

## 3. 上电和开机后的准备

### 3.1 E100c 上电后初始化

每次 E100c 上下电后都要做：

```bash
sudo pkill -x mx_eth_cli; sleep 45              # 先确认没有残留的 mx_eth_cli 占用 FTDI
cd /home/mx/mxfw_tools_e100c
sudo python3 i2c_device.py --dev_idx 0 -i2c pca9539 -s 0x74 --init
sudo ./bringup_e100c.py

# 两个 die 都使能 chip 0~3
for s in 0x38 0x39; do
  printf 'eth port 0 enable chip 0\neth port 0 enable chip 1\neth port 0 enable chip 2\neth port 0 enable chip 3\neth show port brief\nquit\n' \
    | sudo ./mx_eth_cli -c 4 -s $s
done

cd /home/mx/leix/mx_debug_e100c
sudo python3 tsn_disable.py
```

做完后看各网口 `carrier` 是否为 1：

```bash
for i in ens108np0 ens110np0 ens111np0 ens106np0 ens103np0 ens101np0 ens119np0; do
  echo "$i carrier=$(cat /sys/class/net/$i/carrier)"
done
```

如果报 `No answer from FTDI`，是有别的进程（如没退出的 `mx_eth_cli`）占着 FTDI，找到并停掉后再做。

### 3.2 主机重启后

```bash
bash /home/mx/mengx/after_reboot.sh
```

这个脚本做以下事情，最后打印检查结果：

- 停 irqbalance，CPU 调频设为 `performance`；
- `./scripts/e100c.sh setup`：所有测试口静默内核流量、设单 TC、关 pause、每个 NUMA 配 4096 个 2MB 大页；
- 所有网卡 PCIe MaxReadReq 设为 4096。

检查输出里每个网口：`carrier=1`、`TC=1`、`pause=off`、`MRRS=4096`、PCIe 宽度 `x16`。宽度不是 x16（比如 x2）时，那个网口带宽会被限制，需要重启或重新插卡。

只想看状态时：

```bash
cd /home/mx/axi-test
./scripts/e100c.sh check
```

## 4. 测试脚本 e100c.sh

所有命令都在 `/home/mx/axi-test` 下运行。脚本会把实际执行的 `axiperf` 命令完整打印出来（以 `+ sudo` 开头）。

### 4.1 命令格式

| 命令 | 作用 |
|---|---|
| `./scripts/e100c.sh setup` | 准备所有对口的网口（主机重启后做一次） |
| `./scripts/e100c.sh check` | 看所有对口的链路、TC、pause、大页 |
| `./scripts/e100c.sh <对口> refl [rw] [选项]` | 起反射端 |
| `./scripts/e100c.sh <对口> ping [选项]` | 低速打通：每流在途 4，每帧 1 个事务、2 拍，打印前 8 帧 |
| `./scripts/e100c.sh <对口> snd write\|read\|mix\|rw <每流在途> [选项]` | 起发送端跑测试 |
| `./scripts/e100c.sh <对口> cnt snd\|refl` | 每秒看发送口 / 反射口的网卡计数 |
| `./scripts/e100c.sh <对口> cap [帧数]` | 用 tcpdump 抓进反射口的帧（先停反射端），存 `/tmp/refl_in_<名字>.pcap` |
| `./scripts/e100c.sh help` | 看脚本帮助 |

**先起反射端，看到它开始每秒打印后，再起发送端。** 反射端和发送端各开一个窗口。

`snd` 的操作类型：

| 类型 | 含义 |
|---|---|
| `write` | 只写 |
| `read` | 只读 |
| `mix` | 读写混跑：偶数号流写、奇数号流读，拍数相同。`-f 8` 即 4 流写 + 4 流读。经 E100c 做读写并发用这个 |
| `rw` | 同一 MAC 同时读写，两端都要设。只能用于带 VLAN 标签的帧（直连），经 E100c 时程序会拒绝，要用 `mix` |

`<每流在途>`：每条流同时在途的事务数。写至少 2，读至少 4。常用 200。

### 4.2 脚本选项

脚本选项可以放在命令后的任意位置；脚本不认识的参数原样传给 `axiperf`（见[第 6 节](#6-axiperf-参数说明)）。

| 选项 | 含义 | 默认 |
|---|---|---|
| `-f N` | 发送端流数，2 的幂。`mix` 时是读写合计 | `snd` 4，`ping` 1 |
| `-t SEC` | 运行秒数，0 = 一直跑到 Ctrl-C | `snd` 20，`ping` 5 |
| `-n N` | `ping` 只发 N 帧（1~511） | — |
| `-r N` | 反射端核数：1、2、4、8、16。1 = 单队列单核，响应严格按收到的顺序发出 | 4 |
| `-s` | 发送端接收核不和发送核共用物理核。**读和混跑要加，写不要加**（写加了会从约 105G 降到约 87G） | 不加 |
| `-v` | 完整输出：每流结果和调试列 | 精简输出 |
| `--txc N` | 每个上下文 N 个发送核 | 1 |
| `--iso` | 发送端、反射端都加 `--isolate`：同一网口上可以同时跑本方向的发送端和反方向的反射端（双向打流用） | 不加 |
| `--sue` | 发送端改用 SUEv1 帧头（试验性） | 不加 |
| `--dry-run` | 只打印 `ping` / `snd` / `refl` 的命令，不执行 | — |

### 4.3 脚本替你填好的 axiperf 参数

经 E100c 的对口，脚本自动加上这些参数，一般不用再写：

| 参数 | 作用 |
|---|---|
| `--ethertype 0x88ee --min-frame 0` | E100c 帧格式 |
| `--dmac 0,c0:c0:00:a0:00:00 --one-dmac --smac 00:00:00:00:04:01` | 请求的目的 / 源地址（E100c 不校验目的 MAC） |
| `--e100c-port 0,<user.port>` | 请求的 user.port，决定出口 chip（为 0 时不传） |
| `--timeout-us 0` | 不做超时回收：E100c 的 ID 只在收到响应后释放，超时重发会把 ID 耗尽 |
| `--vid 0 --burst 16` | VLAN、发送批量 |
| `--rpack 4` | 读 / 混跑时读请求每帧事务数的默认值（命令里再写 `--rpack` 会覆盖） |
| `--brief` | 精简输出（加 `-v` 去掉） |
| 反射端 `--b-port N --b-tag 0 --r-user 0 --b-pack 1` | 写响应的 port、每帧 1 个 B |
| 反射端 `--rx-split N --rxd 4096` | 多核反射时网卡按随机值把请求均分到 N 个队列（`--iso` 时改为按 tag 分队列） |
| 核绑定 `--lcores` / `-l`、网卡 `-a <BDF>,<devargs>`、`--file-prefix`、`--huge-unlink` | 每个对口固定的核和网卡 |

## 5. 测试命令

下面的“参考结果”是 11-05 ~ 11-06 在当前接线下实测的值，用来判断结果是否正常。每次测完都要看 `err`、`lost` 是否为 0。

### 5.1 打通（新接线、重新上电后先做）

```bash
# 窗口 1
./scripts/e100c.sh 1 refl -r 1 -v
# 窗口 2：只发 10 帧，打印收发的帧
./scripts/e100c.sh 1 ping -n 10
```

发 10 帧、收到 10 个响应即通。收不到时，检查：反射端是否在跑、网口 `carrier`、对口和接线是否对应（[2.3 节](#23-脚本里的对口)）。**没有起反射端时打通测试的结果不可信。**

### 5.2 写

```bash
# 窗口 1
./scripts/e100c.sh 1 refl
# 窗口 2：4 流 × 200，每帧 2 个事务，每事务 4 拍，30 秒
./scripts/e100c.sh 1 snd write 200 -t 30 --pack 2 --beats 4 --id-seq
```

参考结果：约 106G 数据，p50 约 14.6 µs。

改拍数：`--beats 1|2|4`；写要求 `--pack × --beats ≤ 8`。1 拍写数据少，事务率约 60M/s 时数据只有约 31G，属于正常。

### 5.3 读

```bash
# 窗口 1
./scripts/e100c.sh 1 refl
# 窗口 2：4 拍读，每帧 2 个读
./scripts/e100c.sh 1 snd read 200 -s -t 30 --rpack 2 --beats 4 --id-seq
```

参考结果：约 108~115G 数据，p50 约 13~14 µs。

其他拍数：

```bash
./scripts/e100c.sh 1 snd read 200 -s -t 30 --rpack 2 --beats 2 --id-seq   # 2 拍，约 53G
./scripts/e100c.sh 1 snd read 200 -s -t 30 --rpack 4 --beats 1 --id-seq   # 1 拍，约 31G
```

读请求每帧最多 4 个事务（`--rpack 1~4`）。读的 `aruser` 里 `sect_mask` 程序会按拍数自动填好，不要用 `--ar-user-low 0`（会复现读卡死，E100c 要重新上下电）。

### 5.4 读写混跑（单对口）

```bash
# 窗口 1
./scripts/e100c.sh 1 refl              # 4 核；-r 8 时混跑更高
# 窗口 2：8 流 = 4 流写 + 4 流读
./scripts/e100c.sh 1 snd mix 200 -f 8 -s -t 30 --pack 2 --rpack 2 --beats 4 --id-seq
```

参考结果：反射端 4 核约 103~106G（读写各一半），p50 约 30 µs；反射端 8 核约 128G。

### 5.5 多对口并发

```bash
# 窗口 1：三个反射端
for i in 0 1 2; do ./scripts/e100c.sh $i refl --time 50 & done; sleep 6
# 窗口 2：三个发送端（选一行）
for i in 0 1 2; do ./scripts/e100c.sh $i snd write 200 -t 30 --pack 2 --beats 4 --id-seq & done; wait
for i in 0 1 2; do ./scripts/e100c.sh $i snd read 200 -s -t 30 --rpack 2 --beats 4 --id-seq & done; wait
for i in 0 1 2; do ./scripts/e100c.sh $i snd mix 200 -f 8 -s -t 30 --pack 2 --rpack 2 --beats 4 --id-seq & done; wait
```

`--time 50` 让反射端 50 秒后自己退出，比发送端多留时间。参考结果：3 对口写约 315G、读约 315G、混跑约 306G。

多个进程在同一个窗口里跑时，输出会混在一起。给每个进程加前缀方便区分：

```bash
sudo -v   # 先输一次密码，免得几个后台进程同时问密码
for i in 0 1 2; do
  ( ./scripts/e100c.sh $i snd write 200 -t 30 --pack 2 --beats 4 --id-seq 2>&1 | sed -u "s/^/[id$i] /" ) &
done; wait
```

### 5.6 双向写

同一对网口两个方向同时打写，正方向用 `1`，反方向用 `r1`，**两边都要加 `--iso`**：

```bash
# 窗口 1：两个反射端
( ./scripts/e100c.sh 1  refl --iso -r 4 2>&1 | sed -u 's/^/[1 R] /' ) &
( ./scripts/e100c.sh r1 refl --iso -r 4 2>&1 | sed -u 's/^/[r1R] /' ) &
wait
# 窗口 2：两个发送端
sudo -v
( ./scripts/e100c.sh 1  snd write 200 -f 4 -t 30 --pack 2 --beats 4 --id-seq --iso 2>&1 | sed -u 's/^/[1 ] /' ) &
( ./scripts/e100c.sh r1 snd write 200 -f 4 -t 30 --pack 2 --beats 4 --id-seq --iso 2>&1 | sed -u 's/^/[r1] /' ) &
wait
```

参考结果：每方向约 79G，合计约 159G。

每方向 8 流 × 100、反射端 8 核（用 `2` 和 `b2`，或 `1` 和 `b1`）：

```bash
# 四条命令各开一个窗口，或照上面的写法放到后台、加前缀
./scripts/e100c.sh 2  refl --iso -r 8
./scripts/e100c.sh b2 refl --iso -r 8
./scripts/e100c.sh 2  snd write 100 -f 8 -t 30 --pack 2 --beats 4 --id-seq --iso
./scripts/e100c.sh b2 snd write 100 -f 8 -t 30 --pack 2 --beats 4 --id-seq --iso
```

参考结果：11-06 合计约 171G（11-02 旧接线 199.7G）。

### 5.7 两个口进、一个口出

读从 ens108 进，写从 ens111 进，都从 die0 chip2 出到 ens110（两个发送端共用一个反射端）：

```bash
# 窗口 1：反射端 ens110
./scripts/e100c.sh 0 refl
# 窗口 2：两个发送端
sudo -v
( ./scripts/e100c.sh 0  snd read  200 -s -t 60 --rpack 2 --beats 4 --id-seq 2>&1 | sed -u 's/^/[读 ens108] /' ) &
( ./scripts/e100c.sh z1 snd write 200    -t 60 --pack 2  --beats 4 --id-seq 2>&1 | sed -u 's/^/[写 ens111] /' ) &
wait
```

参考结果：读约 87.5G、写约 24.9G，合计约 55M 事务/秒（一个出口的上限）。

读 DNOC 计数时，要在两个发送端都在跑的时候取：die1 的 `ETHI1` 和 `ETHI2` 都应有计数，`UHUBT1` 等于两者之和。

### 5.8 一个口进、两个口出

ens108 跑混跑，写走 user.port 0 出到 ens110，读走 user.port 1 出到 ens106。`--e100c-rport 1` 只改读请求的 user.port：

```bash
# 窗口 1：两个反射端
( ./scripts/e100c.sh 0 refl 2>&1 | sed -u 's/^/[反射 ens110] /' ) &
( ./scripts/e100c.sh 1 refl 2>&1 | sed -u 's/^/[反射 ens106] /' ) &
wait
# 窗口 2：发送端
./scripts/e100c.sh 0 snd mix 200 -f 8 -s -t 30 --pack 2 --rpack 2 --beats 4 --id-seq --e100c-rport 1
```

参考结果：读写各约 71G，合计约 143G、70M 事务/秒。去掉 `--e100c-rport 1` 是对照组（读写都从 ens110 出），约 106G。

同一网口上不能起两个发送端（两个进程都收响应，网卡分不开），所以用一个混跑进程、读写走不同 user.port 的方式。

### 5.9 时延

时延看 `p50us`、`p99us`。比较时延要在相同吞吐下比，小流量、单流时：

```bash
./scripts/e100c.sh z1 refl -r 1
./scripts/e100c.sh z1 snd write 4 -f 1 -t 20 --pack 1 --beats 4 --id-seq     # 每流在途 4，单流
```

直连对比：把两个网口用网线直接对接，用 `d0`~`d2` 跑同样的命令（`d1` 和 `z1` 用同一对网卡和核）。参考：经 E100c 空载 RTT 约 7.7 µs，直连约 6.5~6.7 µs；中等负载下 E100c 多约 1.6~2.0 µs。

### 5.10 长稳

长时间跑用后台脚本，日志写到 `/home/mx/mengx`，断开 ssh 也不会停：

```bash
cd /home/mx/mengx
setsid nohup bash soak3.sh /home/mx/mengx/<日志目录> <每阶段秒数> > soak3.out 2>&1 < /dev/null &
```

`soak3.sh` 让 `0`、`1`、`2` 三对口依次跑读、写、混跑，每对口每秒一行；任一对口掉到基准一半以下时自动读 DNOC 计数。进度看 `<日志目录>/run.log`，每阶段的汇总在 `<阶段>/summary.txt`。

### 5.11 随机测试（数据校验）

`--random` 让每帧的事务数、每个事务的拍数随机变化，数据是可以自校验的随机图样，收到后逐拍检查。**反射端、发送端都要加。**

```bash
# 窗口 1：反射端，--time 要比发送端的 -t 长
./scripts/e100c.sh 2 refl --random --time 60
# 窗口 2：选一行
./scripts/e100c.sh 2 snd write 200 -t 30 --pack 2 --beats 4 --id-seq --random
./scripts/e100c.sh 2 snd read 200 -s -t 30 --rpack 4 --beats 4 --id-seq --random
./scripts/e100c.sh 2 snd mix 200 -f 8 -s -t 30 --pack 2 --rpack 4 --beats 4 --id-seq --random
```

| 项目 | 说明 |
|---|---|
| 包长 | 每帧事务数在 1 ~ `--pack`（读为 `--rpack`）间随机，每个事务拍数在 1 ~ `--beats` 间随机；写帧总拍数不超过 8。`--pack`、`--rpack`、`--beats` 在这里是上限 |
| 数据 | 每拍 64 字节：第一个字的低 8 位是“拍序号 × 16 + 本事务拍数”，其余随机；后 15 个字由第一个字算出。能发现数据被改、拍序错乱、拍数不对、补 0、截断 |
| 写 | 发送端写随机图样，**反射端**逐拍校验 |
| 读 | 反射端回随机图样，**发送端**逐拍校验，并核对响应拍数是否等于请求的拍数 |
| 结果 | 输出最后多一列 `derr`：数据不对的事务数（累计）。读响应拍数和请求不同、但数据完好时算在 `err` 里。前 3 个出错的帧会打印出来 |
| 复现 | 启动时打印 `random: seed=...`；发送端加 `--seed <同一个值>` 会发出同样的随机序列 |
| 性能 | 发送端逐帧现场生成数据，CPU 跑满，比普通模式慢：对口 2 上写约 20G、读约 40G、混跑写 20G + 读 29G |

11-06 在对口 2 上验证：随机写、读、混跑各 30 秒，`derr`、`err` 都是 0；反射端不加 `--random`（回固定数据）时，发送端把每个读都判为错；发送端不加 `--random`（写固定数据）时，反射端把每个写都判为错。

限制：只用于 eth 头（含 E100c 格式），不能和 `--tx-cores` 大于 1、`--r-split` 同用。

### 5.12 抓包

慢速发包时抓包（高速时抓不全）：

```bash
./scripts/e100c.sh 1 refl -r 1 -v --pcap /home/mx/mengx/r.pcap --pcap-count 4000
./scripts/e100c.sh 1 snd read 4 -f 1 -v -t 14 --rpack 1 --beats 4 --count 80 --gap-us 100000 --id-seq --pcap /home/mx/mengx/s.pcap --pcap-count 4000
```

`-f 1 -r 1 --gap-us 100000` 每 100 ms 只发 1 帧，避免 E100c 把多个事务拼到一帧里，方便按帧对照。

命令格式：

```bash
./axiperf <DPDK EAL 参数> -- <axiperf 参数>
```

`--` 前是 DPDK 的参数（核、网卡），后是 axiperf 的参数。`./axiperf --help` 看完整帮助。

参数按用途分成四类，自己重配命令时按顺序看：

| 节 | 内容 |
|---|---|
| [6.2](#62-经-e100c-测试oisa-格式) | **经 E100c 测试**（OISA 格式）要用的参数：固定参数、测试时调的参数、完整命令示例 |
| [6.3](#63-e100c-调试参数) | E100c 调试用的参数，正常测性能不用 |
| [6.4](#64-直连测试标准以太网帧) | **直连测试**（网线直连，不经过 E100c）用的参数 |
| [6.5](#65-sue-和其他试验性参数) | SUE 等试验性参数，现在的测试不用 |

用 `e100c.sh` 时，6.2 的固定参数脚本都已经填好（见 [4.3 节](#43-脚本替你填好的-axiperf-参数)），命令后面只需要加“测试时调的参数”。

### 6.1 DPDK EAL 参数（`--` 之前）

| 参数 | 含义 |
|---|---|
| `-l 44,45-48` | 反射端用的核：第一个是统计核，其余是工作核（每个工作核一个接收队列） |
| `--lcores 0@65,1@66,2@194,...` | 发送端逻辑核到物理核的映射：0 是统计核，之后每条流一个发送核、一个接收核 |
| `-a <BDF>,<devargs>` | 用的网卡及驱动参数，见下表 |
| `--file-prefix NAME` | 进程的大页文件前缀；同时跑多个进程时必须不同 |
| `--huge-unlink` | 退出后不留大页文件 |

核要放在网卡所在的 NUMA（[2.1 节](#21-网卡和-e100c-的连接)），同时跑的进程之间不能重叠。

网卡驱动参数（devargs），脚本里用的值：

| 参数 | 发送端 | 反射端 | 说明 |
|---|---|---|---|
| `dv_flow_en=2` | 不加 | 加 | 反射端 `--rx-split` 需要；`--isolate` 时不加 |
| `txqs_min_inline=1` | 加 | 加 | 发送时把包头内联到描述符 |
| `txq_inline_mpw=128` | 加 | 加 | 多包合并发送时的内联长度 |
| `rxq_pkt_pad_en=1` | 加 | 加 | 接收包按缓存行对齐 |
| `rxq_cqe_comp_en=0` | 加 | 加 | 关接收完成压缩 |

### 6.2 经 E100c 测试（OISA 格式）

#### 6.2.1 固定参数

每条命令都要带，值一般不变。

**发送端：**

| 参数 | 取值 | 说明 |
|---|---|---|
| `--mode sender` | — | 发送端 |
| `--ethertype 0x88ee` | `0x88ee` | E100c 帧格式：不带 802.1Q 标签，帧头为 EtherType + 0000、无 Length。网卡自动开混杂，不核对目的 MAC |
| `--min-frame 0` | 0 | 不补 0（短帧由网卡按以太网最小帧补齐） |
| `--timeout-us 0` | 0 | **必须为 0**：不做超时回收。E100c 的事务 ID 只在收到响应后释放，超时重发会把 ID 耗尽 |
| `--dmac 0,c0:c0:00:a0:00:00` | E100c 样例值 | 请求的目的 MAC；E100c 不校验，填什么都行，但要填 |
| `--one-dmac` | — | 所有流都发往同一个目的 MAC |
| `--smac 00:00:00:00:04:01` | — | 请求的源 MAC，也是 OISA 头第 6~11 字节的初值 |
| `--e100c-port 0,N` | user.port | 端口 0 的请求 user.port 填 N（awuser[51:49] / aruser[48:46]），决定从另一个 die 的哪个 chip 出去（[2.2 节](#22-路由规则)）。N 为 0 时可以不写 |
| `--vid 0` | 0 | E100c 格式的帧没有 VLAN 标签，这个值不起作用，保持 0 |
| `--burst 16` | 16 | 每次发送的帧数 |

**反射端：**

| 参数 | 取值 | 说明 |
|---|---|---|
| `--mode reflector` | — | 反射端 |
| `--ethertype 0x88ee` | `0x88ee` | 同发送端 |
| `--min-frame 0` | 0 | 同发送端 |
| `--b-port N` | 见 [2.2 节](#22-路由规则) | 写响应 B 的 port id（W0[7:5]）。反射端在 die0：0；反射端在 die1：发送口所在 chip xor 2 |
| `--b-tag 0` | 0 | 写响应 EtherType 后的 16 位 |
| `--r-user 0` | 0 | 读响应的 ruser |
| `--b-pack 1` | **1** | 每帧只放 1 个写响应 B（OISA 头只有一个 tag_id，不能合并） |
| `--rxd 4096` | 4096 | 每个接收队列的描述符数，高包率时要大 |
| `--burst 16` | 16 | 攒够多少个响应就发 |
| `--vid 0` | 0 | 同发送端 |

反射端多核时二选一：

| 参数 | 用法 |
|---|---|
| `--rx-split N` | 普通测试用。网卡按随机值把请求均分到 N 个队列（2/4/8/16），每个队列一个核；devargs 要加 `dv_flow_en=2` |
| `--flows N --isolate` | 双向打流用（同一网口上还跑着反方向的发送端）。按请求 tag 低位分到 N 个队列；devargs 不加 `dv_flow_en=2` |

反射端读、写都能处理，不用设 `--op`。

#### 6.2.2 测试时调的参数

**发送端：**

| 参数 | 含义 | 范围 / 默认 | 常用值 |
|---|---|---|---|
| `--op write\|read\|mix` | 只写 / 只读 / 混跑（偶数流写、奇数流读） | write | — |
| `--flows N` | 流数，2 的幂；mix 时是读写合计，至少 2 | 1~16，默认 1 | 写、读 4；混跑 8 |
| `--window N` | 每条流在途事务数；流数 × 窗口 ≤ 1024（mix 时按流数 / 2 算） | 默认 511 | 200 |
| `--pack N` | 写请求每帧事务数；pack × beats ≤ 8 | 默认 2 | 2 |
| `--rpack N` | 读请求每帧事务数 | 1~4 | 4 拍读 2；1 拍读 4 |
| `--beats N` | 每事务拍数，每拍 64B | 1~4，默认 4 | 4 |
| `--time SEC` | 测试时长，0 = 一直跑到 Ctrl-C | 默认 0 | 30 |
| `--id-seq` | 按顺序分配事务 ID，读的性能更高 | 默认空闲 ID 池 | 加 |
| `--e100c-rport N` | 只把读请求的 user.port 改成 N（0~7），写请求仍用 `--e100c-port`；mix 时让读写走不同出口 | 默认不改 | — |
| `--isolate` | 只收响应；同一网口上可以同时跑反方向的反射端（双向打流） | 默认不用 | 双向时加 |
| `--tx-cores N` | 每条流的发送核数，窗口均分；不能和 `--id-seq` 同用 | 1~4，默认 1 | 1 |
| `--brief` | 精简输出：每秒只打合并的一行 | 默认完整输出 | 加 |

发送端的接收核放在哪个物理核上由 `--lcores` 决定（脚本的 `-s` 就是改这个），不是 axiperf 参数。

**反射端：** 只调核数，即 `-l` 里的工作核个数和 `--rx-split N` / `--flows N`，两者要一致。

#### 6.2.3 调试和诊断（E100c 下可用）

| 参数 | 端 | 含义 | 默认 |
|---|---|---|---|
| `--count N` | 发送 | 每个发送上下文只发 N 帧（进程仍跑到 `--time`），0 = 不限 | 0 |
| `--gap-us N` | 发送 | 每 N 微秒最多发 1 帧（慢速抓包用，避免 E100c 拼包），0 = 不限速 | 0 |
| `--dump N` | 两端 | 打印前 N 帧的十六进制 | 0 |
| `--pcap FILE` | 两端 | 把程序收发的帧存成 pcap | 关 |
| `--pcap-count N` | 两端 | 整个进程合计最多抓 N 帧 | 1000 |
| `--hwts` | 两端 | 开网卡接收硬件时间戳，统计网卡收到 → CPU 取包的时延 | 关 |
| `--random` | 两端 | 随机测试：每帧事务数、每事务拍数随机，数据为自校验随机图样；反射端查写数据、发送端查读数据，错误数在 `derr` 列。两端都要加，性能比普通模式低（见 [5.11 节](#511-随机测试数据校验)） | 关 |
| `--seed N` | 两端 | `--random` 的随机种子，用于复现 | 启动时的 TSC（启动时打印） |

性能测试时关掉 `--dump`、`--pcap`、`--hwts`、`--random`。

#### 6.2.4 完整命令示例

`e100c.sh` 实际执行的命令（`--dry-run` 可以打印），对口 `1`：ens111 → ens106，user.port 1。自己重配时照着改网卡、核和 user.port。

反射端（ens106，4 核）：

```bash
sudo ./axiperf --file-prefix axirefl_e100c_d --huge-unlink -l 44,45-48 \
  -a 0000:71:00.0,dv_flow_en=2,txqs_min_inline=1,txq_inline_mpw=128,rxq_pkt_pad_en=1,rxq_cqe_comp_en=0 -- \
  --mode reflector --ethertype 0x88ee --min-frame 0 --vid 0 \
  --rx-split 4 --rxd 4096 --burst 16 --b-pack 1 --b-port 0 --b-tag 0 --r-user 0 --brief
```

发送端（ens111，混跑 8 流 × 200，4 拍；接收核不和发送核共用物理核）：

```bash
sudo ./axiperf --file-prefix axisnd_e100c_d --huge-unlink \
  --lcores 0@65,1@66,2@67,3@68,4@69,5@70,6@71,7@72,8@73,9@74,10@75,11@76,12@77,13@78,14@79,15@80,16@81 \
  -a 0000:dd:00.0,txqs_min_inline=1,txq_inline_mpw=128,rxq_pkt_pad_en=1,rxq_cqe_comp_en=0 -- \
  --mode sender --ethertype 0x88ee --min-frame 0 --timeout-us 0 --vid 0 \
  --dmac 0,c0:c0:00:a0:00:00 --one-dmac --smac 00:00:00:00:04:01 --e100c-port 0,1 \
  --op mix --flows 8 --window 200 --pack 2 --rpack 2 --beats 4 --id-seq --burst 16 --time 30 --brief
```

双向打流时，反方向的反射端（对口 `r1`，在 ens111 上，和上面的发送端共用网口）：

```bash
sudo ./axiperf --file-prefix axirefl_e100c_r1 --huge-unlink -l 118,113-116 \
  -a 0000:dd:00.0,txqs_min_inline=1,txq_inline_mpw=128,rxq_pkt_pad_en=1,rxq_cqe_comp_en=0 -- \
  --mode reflector --ethertype 0x88ee --min-frame 0 --vid 0 \
  --flows 4 --isolate --rxd 4096 --burst 16 --b-pack 1 --b-port 1 --b-tag 0 --r-user 0 --brief
```

这时同一网口上的发送端也要加 `--isolate`。

#### 6.2.5 E100c 下不能用或不要用的参数

| 参数 | 原因 |
|---|---|
| `--op rw` | 要按 VLAN 的 PCP 分读写队列，E100c 帧没有 VLAN 标签；程序会拒绝，读写并发用 `--op mix` |
| `--timeout-us` 非 0 | 超时重发会把 E100c 的事务 ID 耗尽 |
| `--b-pack` 大于 1 | OISA 头只有一个 tag_id，一帧只能放 1 个写响应 |
| `--hdr`、`--no-len` | 改的是标准以太网帧头，`--ethertype` 时不用 |
| `--vid` 非 0、`--promisc` | E100c 帧没有 VLAN 标签；`--ethertype` 时网卡已自动开混杂 |
| `--rx-split` 和 `--isolate` 同用 | 二选一，见 6.2.1 |
| `--tx-cores` 大于 1 和 `--id-seq` 同用 | 程序不支持 |

### 6.3 E100c 调试参数

用于排查读写响应格式、复现问题，正常测性能不用。

| 参数 | 端 | 含义 | 默认 |
|---|---|---|---|
| `--ar-user-low X` | 发送 | 读请求 aruser[29:0] 填 X；默认按拍数自动填 sect_mask（地址 0 时 1~4 拍为 0x03、0x0F、0x3F、0xFF，在 bit 27:20）。**填 0 会复现读卡死**，E100c 要重新上下电 | 自动 |
| `--req-b1 X` | 发送 | 请求 OISA 头第 1 字节（format + packet type） | — |
| `--req-tag 0\|1` | 发送 | 1 = 请求的 tag 填 AXI ID | 0 |
| `--r-beats N` | 反射 | 读响应固定回 N 拍（1~4），不看请求 | 按请求 |
| `--r-echo-aruser N` | 反射 | 读响应的 ruser 取自请求：(aruser >> N) & 0x1FFF（N 为 0~48） | 用 `--r-user` |
| `--r-len-data` | 反射 | 读响应 OISA length 填数据字节数 | 填整帧长 |
| `--r-pack-beats` | 反射 | 读响应 OISA packing_num 填总拍数 | 填事务数 |
| `--r-split N` | 反射 | 读响应每拍一个 R 头（rlen=0），只有最后一拍 rlast=1；1 = 同一帧，2 = 每拍单独一帧 | 不用 |
| `--drop-every N` | 反射 | 每 N 个请求包丢 1 个，模拟丢包；0 = 不丢 | 0 |

### 6.4 直连测试（标准以太网帧）

两个网口用网线直接对接、不经过 E100c 时，用标准以太网帧：802.1Q 标签 + 802.3 Length。脚本里的直连对口是 `d0`~`d2`。和 E100c 测试的区别：

| 参数 | 端 | 直连时的用法 | 默认 |
|---|---|---|---|
| 不加 `--ethertype` | 两端 | 用标准以太网帧头 | — |
| `--hdr eth` | 两端 | 帧头为 VLAN + 802.3 Length（默认就是 eth，不用写） | eth |
| `--vid N` | 两端 | VLAN ID，两端要一致 | 0 |
| `--dmac 0,<反射口 MAC>` | 发送 | **填对端网口的真实 MAC**（`cat /sys/class/net/<网口>/address`），网卡按 MAC 收包 | 02:00:00:00:01:00 |
| `--one-dmac` | 发送 | 所有流发往同一个对端 MAC；反射端用 `--rx-split` 或 `--flows 1` | 按流派生 MAC |
| `--flows N` | 两端 | 不加 `--one-dmac` 时每条流一个 MAC，两端流数要一致，反射端按 MAC 分队列 | 1 |
| `--op rw` | 两端 | 同一 MAC 同时读写，按 PCP 分读写队列；两端都要设，反射端核数加倍 | — |
| `--timeout-us N` | 发送 | 可以用默认值，超时回收计入 lost | 10000 |
| `--b-pack N` | 反射 | 写响应可以合并，1~16 | 1 |
| `--no-len` | 两端 | 帧头不带 Length，事务头紧跟 802.1Q 标签（模拟 E100c 的另一种格式）；两端都设 | 不用 |
| `--promisc` | 两端 | 强制混杂接收；直连默认只收本端 MAC | 不用 |
| `--smac MAC` | 发送 | 不设时用网卡真实 MAC | 网卡 MAC |

E100c 相关参数（`--e100c-port`、`--b-port`、`--b-tag`、`--r-user`、`--isolate`）直连时不用。6.2.2 里的窗口、拍数、每帧事务数等参数直连时同样适用。

直连的完整命令（对口 `d1`：ens111 ↔ ens110，`<ens110 的 MAC>` 换成实际值）：

```bash
# 反射端（ens110）
sudo ./axiperf --file-prefix axirefl_direct_d1 --huge-unlink -l 108,109-112 \
  -a 0000:dc:00.0,dv_flow_en=2,txqs_min_inline=1,txq_inline_mpw=128,rxq_pkt_pad_en=1,rxq_cqe_comp_en=0 -- \
  --mode reflector --vid 0 --rx-split 4 --rxd 4096 --burst 16 --b-pack 16 --brief

# 发送端（ens111）
sudo ./axiperf --file-prefix axisnd_direct_d1 --huge-unlink \
  --lcores 0@65,1@66,2@194,3@67,4@195,5@68,6@196,7@69,8@197 \
  -a 0000:dd:00.0,txqs_min_inline=1,txq_inline_mpw=128,rxq_pkt_pad_en=1,rxq_cqe_comp_en=0 -- \
  --mode sender --vid 0 --dmac 0,<ens110 的 MAC> --one-dmac \
  --op write --flows 4 --window 200 --pack 2 --beats 4 --burst 16 --time 30 --brief
```

用脚本时，直连对口的 MAC 由脚本从网口读取，要在网卡所在的测试主机上运行。

### 6.5 SUE 和其他试验性参数

现在的测试不用。

| 参数 | 含义 | 默认 |
|---|---|---|
| `--hdr sue` | 用 SUEv1 帧头（事务头在第 20 字节） | eth |
| `--gpu-id N` | 本端 GPU ID 基址，流 k 用 N+k | 必填 |
| `--peer-gpu-id N` | 发送端的对端 GPU ID 基址 | 必填 |
| `--sue-ethertype X` | EtherType，须大于 1500 | 0x88B5 |
| `--sue-format N` | Format[2:0] | 0 |
| `--sue-pkttype N` | PktType[4:0] | 0 |
| `--nosplit` | 每个上下文由同一个核收发（默认收发分核，性能更好） | 收发分核 |

### 6.6 核数要求

含 1 个统计核：

- 上下文数 = 网口数 × 流数（`--op rw` 时 × 2）；
- 发送端核数 = 1 + 上下文数 × (发送核数 + 1)；
- 反射端、`--nosplit` 的发送端核数 = 1 + 上下文数（`--rx-split N` 时为 1 + N）。

核数给少了程序会报错退出。

## 7. 输出怎么看

### 7.1 发送端

`--brief` 时每秒一行 `all`；混跑时还有 `w`（写）和 `r`（读）两行。结束时打印 `total/avg` 之后的全程汇总。

```
      txL2G   rxL2G   dataG  txnM/s   p50us   p99us  p999us    maxus    err   lost    bad    miss busy%
all     86.5    17.1    79.0   38.60   19.95   23.40    24.7    719.5      0      0      0       0    77
```

| 列 | 含义 |
|---|---|
| `txL2G` / `rxL2G` | 发 / 收的二层速率（Gbit/s），按帧长算（不足 60 字节按 60），不含 FCS、前导码和帧间隔 |
| `dataG` | AXI 数据吞吐（Gbit/s），只算数据，不含各种头。**比较性能看这一列** |
| `txnM/s` | 每秒完成的事务数（百万） |
| `p50us` / `p99us` / `p999us` | 请求发出到收到响应的时延分位数（µs） |
| `maxus` | 最大时延（累计） |
| `err` | 错误响应、帧头或负载解析出错的数量（累计） |
| `lost` | 超时回收的事务数（累计）；经 E100c 时 `--timeout-us 0`，lost 恒为 0，判断丢失要看吞吐是否持续 |
| `bad` | 目的 MAC 不对或 PCP 和 VC 不一致的帧（累计） |
| `miss` | 网卡侧丢包：imissed + rx_nombuf（累计，只在 `all` 行） |
| `busy%` | 最忙的那个工作核的忙碌比例；会低估负载，不能只看它判断是否 CPU 瓶颈 |
| `derr` | 只在 `--random` 时有：数据校验不对的事务数（累计）；发送端查读数据，反射端查写数据 |

速率和时延分位数是这一秒的；`maxus`、`err`、`lost`、`bad`、`miss` 是从开始累计的。

**写时 `rxL2G` 是写响应**，不含数据：每个事务一个固定大小的 B，所以 1 拍写的收发比（约 0.5）比 4 拍写（约 0.2）大，属于正常。**读时 `txL2G` 是读请求，`rxL2G` 是读响应（带数据）。**

时延和吞吐的关系（Little 定律）：RTT ≈ 在途事务数 ÷ 事务率。在途翻倍、时延也翻倍、吞吐不变，说明前面在排队，再加窗口和流数没有用。

### 7.2 反射端

```
      txL2G   rxL2G    err    bad    miss busy%
all     33.9    36.7      0      0       0    99
```

列的含义同发送端。反射端 `busy%` 接近 100% 时，说明反射端核已跑满，需要加核（`-r 8`）。

### 7.3 结果有效的条件

- 发送端、反射端的 `err`、`bad`、`miss` 都为 0；
- 网卡计数（`cnt`）没有 discards、out_of_buffer、CRC 错误；
- 吞吐逐秒平稳；
- 起 / 停时没有报错。

## 8. E100c DNOC 计数

读一次 E100c 内部各节点的请求 / 响应计数（start、等 1 秒、end），只打印有流量的节点：

```bash
bash /home/mx/mengx/perfsnap.sh /home/mx/mengx/<文件名>.dnoc
```

原始计数存在给定的文件里，屏幕上是汇总。读计数时流量不受影响。

节点命名：chip k 对应 `ETHI(k+1)`、`ETHT(k+1)`、`UHUBI(k+1)`、`UHUBT(k+1)`。

| 节点 | 含义 |
|---|---|
| die1 `ETHIk` | 请求从 die1 chip(k-1) 的 ETH 口进 E100c |
| die1 `UHUBTk` | die1 侧汇聚，去往 die0 |
| die0 `UHUBIk` | 到达 die0 chip(k-1) 的出口 |
| die0 `ETHTk` | 从 die0 chip(k-1) 的 ETH 口发给反射端 |

| 字段 | 含义 |
|---|---|
| `req` / `rsp` | 请求数 / 响应数；正常时每个节点两者相等 |
| `ost_cnt` / `ost_max` | 当前 / 最大在途数；大流量时为 2047（满），停流量后归零 |

例：`0`（ens108 → ens110）的流量经过 die1 `ETHI1` → die1 `UHUBT1` → die0 `UHUBI3` → die0 `ETHT3`。

## 9. 注意事项和常见问题

**操作**

- 先起反射端，再起发送端；停的时候先停发送端。
- **反射端不能比发送端先退出。** 反射端先退时，已经发进 E100c、还没回响应的请求会把这条路径卡住：之后发出去收不到，只能给 E100c 重新上电。反射端用 `--time` 时，要比发送端的 `-t` 长（再加上起发送端前等的几秒）。11-06 因测试脚本里反射端 `--time 40`、发送端 `-t 60`，把对口 `1` 卡住了。
- 停反射端只按**一次** Ctrl-C；连按两次会强制退出，抓包文件写不完整。
- **发送端卡在塌陷里（吞吐掉到 1G 左右、时延约 1 ms）时，不要强制杀进程。** 曾经因此把 E100c 的入口卡住，只能重新上下电。等它自己恢复，或等 `-t` 到时自己退出。
- 停后台测试时，`pkill -f` 的匹配字符串用 `[a]xiperf` 这种写法，避免匹配到执行 pkill 的 shell 自己。
- 同时跑多个对口时，确认核不重叠（`--dry-run` 看命令）。
- 日志和抓包放 `/home/mx/mengx`，不要放 `/tmp`。

**性能配置**

- 读、混跑加 `-s`，写不加。
- 混跑反射端用 `-r 8` 比 4 核高；只读、只写 4 核够了。
- 单流到约 22~24M 事务/秒就上不去了，这是发送端每条流只有一个接收核的限制；要用多流（`-f 4` 以上）。
- 两条流从同一个出口 chip 出去时，合计只有约 55M 事务/秒（单口上限），而且读会挤占写。

**常见问题**

| 现象 | 处理 |
|---|---|
| ping 发出去收不到 | 先确认反射端在跑；查 `carrier`、对口和接线；E100c 刚上电要先做 [3.1 节](#31-e100c-上电后初始化) |
| 发出 N 帧、反射端收到 0 帧，换对口也一样 | 可能是 E100c 入口卡住，需要重新上下电并初始化 |
| bring-up 报 `No answer from FTDI` | 有残留的 `mx_eth_cli` 等进程占着 FTDI，停掉再做 |
| 读跑几十个事务后卡死 | 检查是否用了 `--ar-user-low 0`；卡死后要重新上下电 |
| 某网口吞吐明显偏低 | `after_reboot.sh` 的输出里看 PCIe 宽度，不是 x16 要重启或重新插卡 |
| 进程起不来，报大页或端口占用 | 有残留的 axiperf：`pgrep -af '[a]xiperf'` 查看，正常停掉后再起 |
| 吞吐间歇性掉到约 1G、时延约 1 ms，然后自己恢复 | 已知的塌陷现象，见报告的长稳章节；不要强制停流 |

**E100c 上下电**

- E100c 由 PDU 插孔 S5 供电。**不要动插孔 S4。**
- 只有在芯片卡死、或确认需要时才重新上下电。上电后按 [3.1 节](#31-e100c-上电后初始化) 初始化，再按 [5.1 节](#51-打通新接线重新上电后先做) 逐对打通。
