# E100c OISA 包头定义

本文记录 `axiperf` 在 E100c 模式（`--ethertype 0x88ee`）下实际收发的帧格式，依据是当前代码（`src/hdr.h`、`src/hdr_eth.h`、`src/axi.h`、`src/reflector.c`）和抓包。标为“观察到”的内容只来自抓包，没有规格依据。

多字节字段都是大端。

## 帧结构

```text
0                 12        14     16
| OISA 头（12 字节）| 0x88EE | 2 字节 | AXI 事务 × k | 数据
```

帧头共 16 字节，第一个 AXI 事务从第 16 字节开始。没有 802.1Q 标签。

## 帧头字段

| 字节 | 字段 | 说明 |
|---|---|---|
| 0 | version[7:5]、vc[4:2]、udf[1:0] | version 固定为 6 |
| 1 | format[7:5]、packet_type[4:0] | 取值见下一节 |
| 2~3 | udf[15:13]、length[12:0] | 取值见下一节 |
| 4~5 | status / udf | 发送端来自 `--dmac` 的最后 2 字节，默认 0；响应填 0 |
| 6~7 | tag_id | 请求初值来自 `--smac`，加 `--req-tag` 时填 AXI ID |
| 8~9 | hash[15:10]、dest_id[9:0] | 请求初值来自 `--smac` |
| 10~11 | packing_num[15:10]、source_id[9:0] | source_id 为 `--smac` 的值加流号 |
| 12~13 | EtherType | `0x88EE` |
| 14~15 | type / R / signal / locator | 请求和读响应填 0；写响应填 `--b-tag` |

`--smac` 提供第 6~11 字节的初值。`--dmac` 提供第 0~5 字节的初值，其中 length 总会被覆盖，读请求还会覆盖第 0~1 字节。

## 各类帧的取值

`k` 是本帧事务数，`N` 是每事务拍数，每拍 64 字节。

| 帧 | 字节 0~1 | length（代码写入） | 事务大小 | packing_num |
|---|---|---|---|---|
| 写请求 | `c0 c0`（来自 `--dmac`） | 整帧长：`16 + k × (16 + 64N)` | `16 + 64N` | k |
| 读请求 | `c4 82` | 整帧长：`16 + 16k` | 16 | k |
| 写响应 | `c8 03` | `16 + 12k` | 12 | k |
| 读响应 | `cc 44` | 整帧长：`16 + k × (4 + 64N)`；加 `--r-len-data` 时为 `64Nk` | `4 + 64N` | k |

响应的头部由请求生成：tag_id 原样带回，dest_id 和 source_id 对调。

限制：读每帧最多 4 个事务；写每帧 `事务数 × 拍数` 不超过 8；反射端每个读响应帧最多 8 拍。写响应当前每帧 1 个（`--b-pack 1`）。

## AXI 事务

### AR：读请求（16 字节）

| 字 | 位 | 字段 | 取值 |
|---|---|---|---|
| W0 | 31:28 | frame_type | 3 |
| W0 | 27:19 | AXI ID | 0~511 |
| W0 | 6:4 | aruser.port | `--e100c-port` |
| W0 | 3:0 | aruser.tsn[15:12] | 每端口递增 |
| W1 | 31:20 | aruser.tsn[11:0] | 每端口递增 |
| W3 | 4:3 | arlen | N − 1 |
| W3 | 2:0 | arsize | 6（64 字节） |

其余位填 0，包括地址。

### AW：写请求（16 字节 + 数据）

| 字 | 位 | 字段 | 取值 |
|---|---|---|---|
| W0 | 31:28 | frame_type | 0（writefull） |
| W0 | 27:19 | AXI ID | 0~511 |
| W0 | 18:17 | awlen | N − 1 |
| W0 | 16:13 | writeFull | 每拍 1 位：2 拍 `0011`，4 拍 `1111` |
| W0 | 7:5 | awuser.port | `--e100c-port` |
| W0 | 4:0 | awuser.tsn[15:11] | 每端口递增 |
| W1 | 31:21 | awuser.tsn[10:0] | 每端口递增 |
| W3 | 2:0 | awsize | 6（64 字节） |

其余位填 0，包括地址。数据固定填 `0xA5`。

### R：读响应（4 字节 + 数据）

| 字 | 位 | 字段 | 取值 |
|---|---|---|---|
| W0 | 31:28 | frame_type | 4 |
| W0 | 27:19 | AXI ID | 来自请求 |
| W0 | 18:17 | rlen | N − 1 |
| W0 | 低位 | ruser | `--r-user`，`scripts/e100c.sh` 默认 `0x80` |

数据固定填 `0x5A`。

### B：写响应（12 字节）

| 字 | 位 | 字段 | 取值 |
|---|---|---|---|
| W0 | 31:28 | frame_type | 2 |
| W0 | 27:19 | AXI ID | 来自请求 |
| W0 | 7:5 | port | `--b-port` |

W1、W2 填 0，BRESP 为 0。

## 多流

- 流 f 的 source_id 为基址加 f，AXI ID 满足 `ID ≡ f (mod 流数)`，流数须为 2 的幂。
- 发送端按响应 dest_id 的低位（第 9 字节）分配接收队列。

## E100c 对帧的改写（观察到）

下表来自 2026-11-01 的抓包，测试用 `--smac 00:00:00:00:04:01`。

| 方向 | 字段 | 进入 E100c | 离开 E100c |
|---|---|---|---|
| 读请求 | length | `0x0020` | `0x0000` |
| 读请求 | tag_id | 0 | 等于转发后的 AXI ID |
| 读请求 | source_id | 1 | 0 |
| 读请求 | AXI ID | 发送端的 ID | 被改写，窗口 4 时只在 4 个值之间循环 |
| 读请求 | W0 port | p | p + 2 |
| 读请求 | W3 | 1 拍 `0006`，2 拍 `000e` | 都是 `0406` |
| 读响应 | length | 整帧长 | 数据字节数：1 拍 `0x40`，2 拍 `0x80` |
| 读响应 | tag_id | 转发后的 AXI ID | 发送端的 AXI ID |
| 读响应 | dest_id | 0 | 1 |
| 读响应 | packing_num | 事务数 | 拍数：1~4 拍时为 1~4 |

发送端软件抓到的读请求是 32B，网卡发出时补到 60B，所以反射端抓到的是 60B。

## 抓包样例

每组 4 位十六进制是 2 字节，只列前 32 字节。

```text
发送端发出的读请求，1 拍，32B
c482 0020 0000 0000 0000 0401 88ee 0000  3000 0010 0000 0000 0000 0000 0000 0006

发送端发出的读请求，2 拍，32B
c482 0020 0000 0000 0000 0401 88ee 0000  3000 0010 0000 0000 0000 0000 0000 000e

反射端收到的读请求，60B
c482 0000 0000 0007 0000 0400 88ee 0000  3038 0034 e900 0000 0000 0000 0000 0406

反射端发出的读响应，1 拍，84B
cc44 0054 0000 0007 0000 0400 88ee 0000  4038 0080 5a5a 5a5a ...

发送端收到的读响应，1 拍，84B
cc44 0040 0000 0003 0001 0400 88ee 0000  4018 0008 5a5a 5a5a ...

发送端收到的读响应，2 拍，148B
cc44 0080 0000 0000 0001 0800 88ee 0000  4002 0000 5a5a 5a5a ...
```

## 待确认

- 反射端写的 length 是整帧长，E100c 发出的是数据字节数。改成数据字节数后，2 拍读仍然卡死。
- E100c 发出的读响应，packing_num 等于拍数（1~4 拍实测），反射端默认写事务数。反射端改成拍数（`--r-pack-beats`）后，2 拍仍然卡死。
- R 的 W0 bit 3 在 `AXI包格式_v5_读写.xlsx` 里是 rlast（待确认）。E100c 发出时 1 拍为 1，2~4 拍为 0；反射端默认发 0，置 1（`--r-user 0x88`）后 2 拍仍然卡死。
- 读请求 W3 的 `0406` 含义没有确认，反射端也无法从中分辨 1 拍和 2 拍。
- 代码不填地址和其余 user 位，E100c 是否有要求没有确认。
