# E100c OISA 包头定义

本文记录 `axiperf` 在 E100c 模式（`--ethertype 0x88ee`）下收发的帧格式，依据是当前代码（`src/hdr.h`、`src/hdr_eth.h`、`src/axi.h`、`src/reflector.c`）、aruser 规格说明和抓包。标为“观察到”的内容只来自抓包，没有规格依据。

多字节字段都是大端。

**读请求要点：aruser 的 `sect_mask` 必须按读长度填写。** 填 0 时多拍读累计几十个响应后 E100c 卡死。详见[读请求 aruser](#读请求-aruser)。

## 帧结构

```text
0                 12        14     16
| OISA 头（12 字节）| 0x88EE | 2 字节 | AXI 事务 × k | 数据
```

帧头共 16 字节，第一个 AXI 事务从第 16 字节开始。没有 802.1Q 标签。

## 帧头字段

| 字节 | 字段 | 说明 |
|---|---|---|
| 0 | version[7:5]、vc[4:2]、udf[1:0] | version 固定为 6 |
| 1 | format[7:5]、packet_type[4:0] | 取值见下一节 |
| 2~3 | udf[15:13]、length[12:0] | 取值见下一节 |
| 4~5 | status / udf | 发送端来自 `--dmac` 的最后 2 字节，默认 0；响应填 0 |
| 6~7 | tag_id | 请求初值来自 `--smac`，加 `--req-tag` 时填 AXI ID |
| 8~9 | hash[15:10]、dest_id[9:0] | 请求初值来自 `--smac` |
| 10~11 | packing_num[15:10]、source_id[9:0] | source_id 为 `--smac` 的值加流号 |
| 12~13 | EtherType | `0x88EE` |
| 14~15 | type / R / signal / locator | 请求和读响应填 0；写响应填 `--b-tag` |

`--smac` 提供第 6~11 字节的初值。`--dmac` 提供第 0~5 字节的初值，其中 length 总会被覆盖，读请求还会覆盖第 0~1 字节。

## 各类帧的取值

`k` 是本帧事务数，`N` 是每事务拍数，每拍 64 字节。

| 帧 | 字节 0~1 | length（代码写入） | 事务大小 | packing_num |
|---|---|---|---|---|
| 写请求 | `c0 c0`（来自 `--dmac`） | 整帧长：`16 + k × (16 + 64N)` | `16 + 64N` | k |
| 读请求 | `c4 82` | 整帧长：`16 + 16k` | 16 | k |
| 写响应 | `c8 03` | `16 + 12k` | 12 | k |
| 读响应 | `cc 44` | 整帧长：`16 + k × (4 + 64N)` | `4 + 64N` | k |

响应的头部由请求生成：tag_id 原样带回，dest_id 和 source_id 对调。

`--random` 时每帧的事务数 k 在 1~`--pack`（读为 `--rpack`）之间随机，每个事务的拍数 N 也各自随机（1~`--beats`，写帧总拍数 ≤ 8），上表的 length 按各事务实际拍数相加，例如写请求为 `16 + Σ(16 + 64Nᵢ)`。

一个事务只有一个事务头和一个 AXI ID，拍数只体现在 arlen / awlen / rlen 里。两个事务才有两个事务头。

限制：读每帧最多 4 个事务；写每帧 `事务数 × 拍数` 不超过 8；反射端每个读响应帧最多 8 拍。写响应当前每帧 1 个（`--b-pack 1`）。

## AXI 事务

### AR：读请求（16 字节）

| 字 | 位 | 字段 | 取值 |
|---|---|---|---|
| W0 | 31:28 | frame_type | 3 |
| W0 | 27:19 | AXI ID | 0~511 |
| W0 | 18:0 | aruser[60:42] | port、tsn 高位，见下 |
| W1 | 31:0 | aruser[41:10] | tsn 低位、`sect_mask` 等，见下 |
| W2 | 31:22 | aruser[9:0] | 见下 |
| W2 | 21:0 | araddr[48:27] | 当前填 0 |
| W3 | 31:5 | araddr[26:0] | 当前填 0 |
| W3 | 4:3 | arlen | N − 1 |
| W3 | 2:0 | arsize | 6（64 字节） |

### 读请求 aruser

aruser 在 UHUB/SMP 接口是 [29:0]，在 ETH 接口是 [48:0]。

| aruser 位 | 线上位置 | 字段 | 规格说明 | 当前填写 |
|---|---|---|---|---:|
| 0 | W2[22] | vf | virtual function | 0 |
| 3:1 | W2[25:23] | vfid[2:0] | vf=1 时才有效，否则填 0 | 0 |
| 4 | W2[26] | tport | DNOC 专用，client 填 0 | 0 |
| 10:5 | W1[0]、W2[31:27] | client_id[5:0] | | 0 |
| 11 | W1[1] | rp_l2 | L2C 替换策略；非 xcore client 由配置寄存器决定，默认 0 | 0 |
| 16:12 | W1[6:2] | rc[4:0] | L2C 驻留控制；非 xcore client 默认 0 | 0 |
| 17 | W1[7] | snoop | 数据路径上的 cache snoop | 0 |
| 19:18 | W1[9:8] | sect_mode[1:0] | L2 预取大小：0 默认，1 为 128B，2 为 256B；不改变返回数据大小 | 0 |
| **27:20** | **W1[17:10]** | **sect_mask[7:0]** | **目标 sector，见下** | **按拍数计算** |
| 28 | W1[18] | ro | PCIe 宽松排序 | 0 |
| 29 | W1[19] | perfen | xcore 使用；非 xcore client 默认 0 | 0 |
| 45:30 | W0[3:0]、W1[31:20] | tsn | 事务序号，只存在于 ETHI/ETHT 接口 | 每端口递增 |
| 48:46 | W0[6:4] | port_id | 相关 UCIe 的 port id，只存在于 ETHI/ETHT 接口 | `--e100c-port`；设了 `--e100c-rport` 时用它 |

### sect_mask

每位表示两个 128 字节 cache entry 中一个 32 字节的位置，最大支持 256 字节请求，请求不能跨 256 字节对齐边界。

```text
N = ROUNDUP(2^arsize × (arlen + 1) / 总线字节数)

64 字节总线：sect_mask[7:0] = {N{2'b11}} << {araddr[7:6], 1'b0}
32 字节总线：sect_mask[7:0] = {N{1'b1}}  << araddr[7:5]
```

E100c 这边 arsize=6，用 64 字节总线的公式：

| 拍数 | arlen | sect_mask（地址 0） | W1[19:0] |
|---:|---:|---:|---:|
| 1 | 0 | `0x03` | `0x00c00` |
| 2 | 1 | `0x0F` | `0x03c00` |
| 3 | 2 | `0x3F` | `0x0fc00` |
| 4 | 3 | `0xFF` | `0x3fc00` |

发送端默认按 `--beats` 自动填（地址固定为 0，不移位）；`--random` 时按每个事务自己的拍数填。`--ar-user-low X` 可手动指定 aruser[29:0]。**使用真实地址时必须按公式移位，这部分代码还没写。**

### AW：写请求（16 字节 + 数据）

| 字 | 位 | 字段 | 取值 |
|---|---|---|---|
| W0 | 31:28 | frame_type | 0（writefull） |
| W0 | 27:19 | AXI ID | 0~511 |
| W0 | 18:17 | awlen | N − 1 |
| W0 | 16:13 | writeFull | 每拍 1 位：2 拍 `0011`，4 拍 `1111` |
| W0 | 7:5 | awuser.port | `--e100c-port` |
| W0 | 4:0 | awuser.tsn[15:11] | 每端口递增 |
| W1 | 31:21 | awuser.tsn[10:0] | 每端口递增 |
| W3 | 2:0 | awsize | 6（64 字节） |

其余位填 0，包括地址。数据默认固定填 `0xA5`；`--random` 时为自校验图样（见下文“随机测试的数据”）。awuser 的其余位没有规格说明。

### R：读响应（4 字节 + 数据）

| 字 | 位 | 字段 | 取值 |
|---|---|---|---|
| W0 | 31:28 | frame_type | 4 |
| W0 | 27:19 | AXI ID | 来自请求 |
| W0 | 18:17 | rlen | N − 1 |
| W0 | 16:4 | ruser[12:0] | 默认 0；`--r-echo-aruser N` 时取 `(aruser >> N) & 0x1FFF` |
| W0 | 3 | rlast | 代码填 0（`AXI包格式_v5_读写.xlsx` 里的名称，待确认）；`--r-split` 时最后一拍填 1 |
| W0 | 2:1 | RRESP | 0 |
| W0 | 0 | rsv | 0 |

`--r-user X` 把 X 原样或进 W0 的低位（不移位，例如 `0x80` 落在 W0 bit 7，即 ruser bit 3），用于调试。

数据默认固定填 `0x5A`；`--random` 时为自校验图样。

### B：写响应（12 字节）

| 字 | 位 | 字段 | 取值 |
|---|---|---|---|
| W0 | 31:28 | frame_type | 2 |
| W0 | 27:19 | AXI ID | 来自请求 |
| W0 | 7:5 | port | `--b-port` |

W1、W2 填 0，BRESP 为 0。

## 多流

- 流 f 的 source_id 为基址加 f，流数须为 2 的幂。
- 单写、单读：AXI ID 满足 `ID ≡ f (mod 流数)`。
- 读写并发用 `--op mix`：偶数流写、奇数流读，读写拍数相同。读、写各用一套 ID（AXI 的 AR、AW ID 本来独立），流 f 用 `ID ≡ f/2 (mod 流数/2)`；线上读和写可以同时使用相同的 ID，实测没有问题。
- 读写走不同 E100c 出口时，`--e100c-rport N` 让读请求的 port_id 单独填 N，写请求仍用 `--e100c-port`。
- 发送端按响应 dest_id 的低位（第 9 字节）分配接收队列。E100c 把不同流的响应合并进同一帧时，按响应类型（B / R）和 ID 低位找回所属流。

## 随机测试的数据

`--random` 时写数据（发送端填）和读数据（反射端填）每个 64 字节拍各自可校验，收端只看本拍就能判断对错：

- 第 0 个 32 bit 字（大端）：低 8 位 = `(拍序号 << 4) | 本事务拍数`，高 24 位随机。
- 第 1~15 个字：从第 0 个字开始依次做 xorshift32（`x ^= x << 13; x ^= x >> 17; x ^= x << 5`）。

能发现数据被改、拍序错乱、拍数不对、补 0 或截断。反射端校验写数据，发送端校验读数据，不对的事务数在输出的 `derr` 列。启动时打印 `random: seed=...`，用 `--seed` 可复现同一序列。

## 区分请求和响应

第 0 字节的 bit 3：请求（`c0` 写、`c4` 读）为 0，响应（`c8` 写、`cc` 读）为 1。`--isolate` 用它让同一网口上的发送端只收响应、反射端只收请求，这样一个网口可以同时跑两个方向。反射端多核时，按请求 tag_id 的低位（第 7 字节）分队列；tag_id 是 E100c 转发后的 AXI ID。

## E100c 对帧的改写（观察到）

下表来自 2026-11-02 的抓包（`ok_*beat_*.pcap`，id 1，`--smac 00:00:00:00:04:01`）。

| 方向 | 字段 | 进入 E100c | 离开 E100c |
|---|---|---|---|
| 读请求 | length | `0x0020` | `0x0000` |
| 读请求 | tag_id | 0 | 等于转发后的 AXI ID |
| 读请求 | source_id | 1 | 0 |
| 读请求 | AXI ID | 发送端的 ID | 被改写，窗口 4 时只在少数几个值之间循环 |
| 读请求 | W0 port | p | p + 2 |
| 读请求 | tsn | 发送端的值 | E100c 自己的累计值，上电后才和发送端一致 |
| 读请求 | W1[19:0]、W3 | 按拍数填写 | 不变 |
| 读响应 | length | 整帧长 | 数据字节数：1 / 2 / 4 拍为 `0x40` / `0x80` / `0x100` |
| 读响应 | tag_id | 转发后的 AXI ID | 发送端的 AXI ID |
| 读响应 | dest_id | 0 | 1 |
| 读响应 | packing_num | 事务数 | 总拍数：1 / 2 / 4 拍为 1 / 2 / 4 |
| 读响应 | W0 低 16 位 | 0 | 1 拍 `0x0008`，多拍 `0x0000` |

其他观察：

- 发送端软件抓到的读请求是 32B，网卡发出时补到 60B，所以反射端抓到的是 60B。
- E100c 可能把两个读请求合并成一帧转给反射端。2 拍以上的合并响应（如 280B）在发给发送端时被拆成两帧，1 拍的合并响应（152B）保持合并。100ms 间隔慢发时不会合并。
- 请求 `sect_mask=0` 时，反射端收到的 W3 变成 `0x0406`，arlen 丢失，响应拍数和请求不符时 E100c 丢弃响应。这时用 `--r-beats` 强制回拍数。

## 抓包样例

每组 4 位十六进制是 2 字节。样本来自 id 1，帧头后依次是 W0~W3（请求）或 W0（响应）。

```text
4 拍
发送端发请求  c482 0020 0000 0000 0000 0401 88ee 0000 | 3000 0010 0003 fc00 0000 0000 0000 001e
反射端收请求  c482 0000 0000 0000 0000 0400 88ee 0000 | 3000 003a 1753 fc00 0000 0000 0000 001e
反射端回响应  cc44 0114 0000 0000 0000 0400 88ee 0000 | 4006 0000 5a5a ...（276B）
发送端收响应  cc44 0100 0000 0000 0001 1000 88ee 0000 | 4006 0000 5a5a ...（276B）

2 拍
发送端发请求  c482 0020 0000 0000 0000 0401 88ee 0000 | 3000 0010 0000 3c00 0000 0000 0000 000e
反射端收请求  c482 0000 0000 0000 0000 0400 88ee 0000 | 3000 003a 1250 3c00 0000 0000 0000 000e
反射端回响应  cc44 0094 0000 0000 0000 0400 88ee 0000 | 4002 0000 5a5a ...（148B）
发送端收响应  cc44 0080 0000 0000 0001 0800 88ee 0000 | 4002 0000 5a5a ...（148B）

1 拍
发送端发请求  c482 0020 0000 0000 0000 0401 88ee 0000 | 3000 0010 0000 0c00 0000 0000 0000 0006
反射端收请求  c482 0000 0000 0000 0000 0400 88ee 0000 | 3000 003a 0d50 0c00 0000 0000 0000 0006
反射端回响应  cc44 0054 0000 0000 0000 0400 88ee 0000 | 4000 0000 5a5a ...（84B）
发送端收响应  cc44 0040 0000 0000 0001 0400 88ee 0000 | 4000 0008 5a5a ...（84B）
```

## 待确认

- `sect_mask=0` 时为什么 1 拍不卡、多拍累计几十个才卡（慢发 4 拍完成 15 个，2 拍完成 45 或 56 个）。规格没有说明。
- R 的 W0 bit 3 是否就是 rlast。E100c 发出时 1 拍为 1，多拍为 0；反射端多拍时填 1，E100c 发出的仍是 0。
- ruser 和 aruser 除上表外的位是否有要求。只填 `sect_mask` 时读写都能跑。
- awuser 的详细定义。C700 抓包里 awuser 的其余位也不是 0，当前填 0 能跑。
- 读请求 W3 的 `0x0406` 含义。
